# 室内 RGB-D LLM 回环检测 MVP 设计文档

**日期：** 2026-05-21

## 一、目标

构建一个独立的室内 RGB-D 回环检测研究原型，第一版重点完成以下能力：

- 使用 OneFormer 生成全景分割区域
- 对关键锚点目标做轻量语义重标定
- 在构图前进行面向回环的静态性筛选
- 将筛选后的目标投影到 3D
- 导出紧凑、结构化的场景图，供后续 LLM 回环推理使用

第一版 MVP 不包含端到端回环评测，也不接入在线 LLM 推理。
当前目标是先把“每帧稳定场景图构建”这条主链路跑通，并产出可靠中间结果。

## 二、范围

本次 MVP 包含：

- ScanNet RGB-D 单帧数据读取
- 基于 OneFormer 的全景分割
- 面向高价值室内目标的锚点重标定
- 静态性感知的目标筛选
- 基于深度的 2D 到 3D 投影
- 离散对象关系图构建
- JSON 导出与简单可视化叠加输出

本次 MVP 不包含：

- 完整回环检索与排序
- LLM CoT 推理模块
- 新模型训练
- 多序列批量评测
- 端到端性能指标对比

## 三、当前约束与背景

用户已有一个独立旧项目，并明确要求不得改动。
本项目必须作为新工程单独实现，目录固定在：

`Desktop/indoor-llm-loop-closure`

当前研究方向已经确定为：

- 室内场景
- RGB-D 输入
- 后续由 LLM 作为最终判别器
- 尽量少训练或不训练
- 以结构化场景图推理为主，而不是自由文本描述

## 四、推荐方案

项目采用轻量包结构，不复用旧工程的 phase 编号或接口。

第一版推荐流程为：

1. 读取一帧 ScanNet RGB-D
2. 运行 OneFormer 全景分割
3. 仅对高价值锚点目标做重标定
4. 计算静态性并保留稳定或半稳定目标
5. 将保留目标投影到 3D
6. 构建紧凑对象关系图
7. 导出机器可读与人可读结果

推荐这条路线的原因是：
它优先验证整套方法中风险最高、也是后续 LLM 推理最依赖的部分，即如何把噪声较大的 RGB-D 观测转成稳定的对象级图表示。

## 五、备选方案比较

### 方案 A：纯脚本原型

优点：

- 起步最快
- 结构最少

缺点：

- 后续接入 LLM 推理时容易混乱
- 分割、构图、导出逻辑容易耦合

### 方案 B：轻量包结构

优点：

- 模块边界清晰
- 便于后续扩展到检索和 LLM 模块
- 对 MVP 来说复杂度合适

缺点：

- 比纯脚本多一点初始化工作

### 方案 C：完整研究框架

优点：

- 长期扩展性最好

缺点：

- 当前阶段过重
- 会在验证核心方法前引入过多架构成本

最终采用方案 B。

## 六、总体架构

### 1. 输入层

输入层负责读取一帧 ScanNet 的 RGB 图、深度图和相机内参。
位姿信息后续可以接入，但 MVP-v1 不作为必要输入。

### 2. 全景分割层

对 RGB 图运行 OneFormer，得到全景分割结果及初始语义标签。

这一层负责：

- 同时解析 `thing` 和 `stuff`
- 保留 mask 几何信息
- 保留每个分割区域的置信度、包围框和基本属性

### 3. 锚点重标定层

只对高价值室内锚点做轻量重标定，不对所有区域做开放词汇识别。

优先处理的目标类别包括：

- bed
- desk/table
- chair
- sofa
- cabinet/shelf
- monitor/display
- sink/toilet
- window/door

这一层的目标不是彻底重做识别，而是让后续构图使用的关键语义更稳定。

### 4. 静态性筛选层

为每个目标分配一个静态性等级：

- `hard_static`
- `soft_static`
- `dynamic`

筛选依据包括：

- 类别先验
- 几何稳定性
- 支撑关系
- 观测质量

默认情况下，被判为 `dynamic` 的目标不进入后续场景图。

### 5. 3D 投影层

利用深度图和相机内参，将筛选后的 2D 目标 mask 投影到 3D。

每个目标至少输出：

- 3D 中心
- 近似尺寸
- 距地高度
- 支撑类型
- 是否贴墙

为了降低噪声，3D 属性估计应采用鲁棒统计，而不是直接对原始深度做简单均值。

### 6. 关系图构建层

基于目标节点构建紧凑的离散对象关系图。

支持的关系类型包括：

- `left_of`
- `right_of`
- `in_front_of`
- `behind`
- `near`
- `far`
- `higher_than`
- `lower_than`
- `on`
- `against_wall`

图必须保持紧凑和稳定，只保留局部、高置信、对后续推理有用的关系。

### 7. 导出层

输出 JSON 结果以及一张基础叠加可视化图，便于检查结果是否合理。

## 七、数据流

整体数据流如下：

1. 读取 RGB、depth、intrinsics
2. 运行 OneFormer
3. 对锚点目标做重标定
4. 计算静态性
5. 过滤或降权不稳定目标
6. 投影生成 3D 节点
7. 构建对象关系图
8. 导出 JSON 和 overlay 图

## 九、MVP 第一阶段交付物

第一阶段至少要能稳定产出以下结果：

- 一个可运行的单帧场景图导出命令
- 合法的 `scene_graph.json`
- 可读的叠加可视化图
- 一个用于 ScanNet 样例的配置文件

## 十、主要风险

- OneFormer 对稀有室内目标的标签可能不稳定
- 深度投影在遮挡或空洞区域可能带来较大噪声
- 如果关系筛选不够严格，图会过密，不利于后续推理

对应缓解策略：

- 只对关键锚点做重标定
- 3D 属性估计采用鲁棒统计
- 关系图只保留高置信局部关系

## 十一、测试要求

第一阶段至少验证以下内容：

- 数据读取模块可以正确读取单帧 RGB-D
- 整条流程可以正常写出 JSON，而不是中途崩溃
- 输出图中包含稳定对象节点和离散关系
- overlay 导出功能可正常完成
